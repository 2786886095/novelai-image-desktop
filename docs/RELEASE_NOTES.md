# 更新记录

## Latest · 转换后 WebP 的历史与素材可见性修复

### 修复范围与证据边界

- #79 后来澄清为“历史与素材中无法显示被转换为 WebP 格式的图片”。此前日期刷新竞态修复不作为本次 WebP 问题已解决的证据；报告者未提供原始文件或具体步骤，本轮针对真实文件替换所复现的索引丢失路径处理，不声称覆盖所有未知转换方式。
- 原 PNG／JPEG（`.png`、`.jpg`、`.jpeg`）已缺失时，仅对同目录、同名主干、唯一普通非链接、结构和尺寸吻合的 WebP 重链历史路径。保留记录 ID、原日期／创建时间、参数、分组、原生成来源哈希及独立收藏，不重新生成、不转码，也不修改图片字节。
- 原图仍在时不自动改用新文件；不跨目录猜图，不从多候选、损坏、不可访问或链接文件自动重链。不自动扫描并导入任意 WebP，另存副本、改名或跨目录移动不属于同名替换恢复。
- 桌面显式恢复入口只从可用的本机索引备份中增量合并能确认转换对应关系的历史记录，当前记录优先；不回退设置、账号或收藏，不在启动时无提示复活主动移除的记录。备份不含原记录时不能重建原有信息。
- 移动端没有同等的旧历史备份，不会假称能恢复此前已清理的记录。iOS 文件提供方读取必须继续使用既有授权目录与协调访问，不扩大路径权限；离线、撤权或不确定结果不当作文件已删除。

### 发行方式与未完成项

- 本轮继续处理未完成的 WebP 反馈，并按维护者指定的正式版本发布；沿用该操作中“修复后直接发布、不追加整套验收”的要求。必要的修复回归、编译、打包、制品核对与源码回滚完整性分别记录，不追加全量、原生设备或 GPU 验收，也不把既有完整验收门改写为通过。
- 本轮进一步澄清的 WebP 路径修正由 Codex 执行；不冒称在 Claude 会话限额下又运行了新的 Claude 方案或完整实现。当前源码、实际工作流、制品、签名和校验值以 Latest 的真实附件及 verification.json 为准；不预填测试数量、构建成功或上传完成。
- 完整功能矩阵的 187 个必需单元未因本次定点修复自动认证；Windows 本地 Agent 和画风迭代仍仅 Windows，其他平台不支持项不计通过。Linux 的支持基线与已知限制未在本轮扩大。
- 若提供未签名 IPA，仍需自行签名／侧载，不能直接安装到普通 iPhone，也不等于 App Store／TestFlight 发行。Windows Authenticode、macOS 公证及软件内更新能力以真实制品和发行证据为准，不提前承诺。
