# 图片元数据防回归

## 已确认的原因

显示图片与读取生成参数是两回事。旧读取逻辑并未覆盖官方参数的全部存储方式：PNG 文本、WebP EXIF 以及透明通道最低位里的 gzip/JSON。无效或空的外层 Comment、普通 Software 字段不能视为已经找到生成参数，否则会提前停止隐藏数据回退。

此前 PNG 像素读取只覆盖部分 8-bit 非交错编码；16-bit、灰度透明、调色板和 Adam7 等编码需要正确解码后再读透明通道。移动端原有 WebP 解码库也存在兼容缺口。不同入口曾走不同的同步/异步读取路径，单独修复一个解析器并不足够。

旧测试覆盖不足可由同一组 24 个官方兼容中性样本直接复现：本次编码覆盖扩展前的候选（已经含上一轮基础修复，并非原始发行包），桌面后端与真实浏览器均只能恢复 5 个，移动端能恢复 16 个；扩展后都是 24 个。不能据此断言某个开发者的动机，或断言用户用了哪款软件、在哪一步破坏了文件。

## 自动检查

- `npm run test:metadata`：文字/EXIF/隐藏数据与安全边界测试；真实工作台文件选择、路径加载和 MCP 工具入口；所有共享样本在关闭 Node 集成的真实 Electron 浏览器中读取，不能以 Sharp 模拟浏览器替代。
- 固定样本 SHA、样本数量及预期字段，防止删掉失败样本后假通过；读取前后图片字节不变。
- 结构检查防止界面/MCP 工具入口退回旧同步解析；它只是代码连接检查，不替代运行时验收。
- PR/主分支触发专项工作流；正式桌面构建打包前也必须运行专项步骤。
- 正式发布脚本逐一验证 Windows 与 macOS 两个桌面构建的同名专项步骤。未执行、跳过、失败、取消都拒绝；复用旧构建也不能绕过。
- 私有仅构建模式可按既有约定跳过验收，但不能正式发布。没有配置远端必需检查规则，也没有将本地测试冒充已运行的远端 CI。

## 边界及后续维护

本轮扩展官方 PNG/WebP 元数据，保留已有 JPEG EXIF 兼容，不承诺 GIF/AVIF/HEIC 都具有官方生成参数。原图被重新编码、截图、压缩或裁剪后可能丢失/损坏隐藏数据；参数不存在时不可编造。

用户提供的 20 张文件中，18 张参数已经恢复。另两张的已测试载体分别没有找到参数、隐藏 gzip 数据损坏；“官网读取的是同一份字节”尚未独立核验。不能把它们报告为已恢复。

现有读取有字节数、像素数及解压限制。新增格式或扩大限制时，必须先增加中性真实编码样本，并同步更新桌面、浏览器及样本数量断言，保留原有失败样本。依赖升级需运行专项、全量测试及 Windows / macOS 原生导入验收；仅 typecheck 通过不等于运行时通过。

本机 Windows 原生浏览器已验证；macOS 原生验收仍需对应环境，不作百分之百永不复发的保证。
